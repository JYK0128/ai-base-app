# 최소 폴백 설계 표준

- 이 스킬은 데이터·로직 계층에서 필수 값을 검증하고, 경계 입력은 원형을 유지한 채 검증하며, 입력값 변환은 하지 않고, 실패를 현재 지점에서 드러내 원인 파악을 단순화한다.
- 표현 계층에서는 로딩, 오류, 빈 상태를 시각적으로 보완해 사용자 경험을 유지한다.

---

## 1. 데이터 및 비즈니스 계층에서의 Fail-Fast 원칙

### 1.1 환경변수 검증

- DB 연결 문자열, 인증 키, 외부 API 키를 실행 전에 모두 채운다.
- 하나라도 비어 있으면 서버를 시작하지 않는다.

### 1.2 전달값 보존

- 요청, 응답, DB 조회 결과는 다음 단계로 넘기기 전에 임의값이나 추론값으로 덮지 않는다.
- 전달되는 값은 원본 의미를 유지한다.

### 1.3 입력값 변환 금지

- 입력값은 검증 대상이지, 이 단계에서 가공할 대상이 아니다.
- 공백 제거, 대소문자 정규화, 빈 항목 제거 같은 변환도 하지 않는다.
- 필요한 형태 변경은 입력 경계 밖에서 명시적으로 처리한다.
- 내부 로직에 들어가는 값은 검증을 통과한 원형 그대로 사용한다.

### 1.4 입력값 검증

- 외부 입력은 내부 계약에 맞는지 검증한 뒤에만 사용한다.
- 값의 존재, 타입, 형식이 맞지 않으면 즉시 실패한다.

---

## 2. 표현 계층에서의 Graceful Fallback 원칙

### 2.1 런타임 오류 처리

- 개별 컴포넌트나 라우트에서 런타임 오류가 발생하면 에러 경계로 격리하고 복구 UI를 제공한다.
- 오류 복구에는 재시도 동작과 사용자 안내를 포함한다.

### 2.2 로딩 및 빈 상태 시각화

- 로딩 상태와 빈 상태에는 Skeleton 또는 안내 템플릿을 제공한다.
- 화면은 현재 상태를 한눈에 파악할 수 있는 시각적 피드백을 유지한다.

### 2.3 대체 그래픽 제공

- 외부 미디어 자원이나 이미지 로딩 실패에는 대체 그래픽을 제공한다.
- 이미지 실패 시에도 안정적인 대체 표시를 렌더링한다.
