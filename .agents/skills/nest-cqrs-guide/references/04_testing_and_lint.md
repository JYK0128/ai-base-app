# CQRS 테스트 및 린트 가이드

- 본 문서는 CQRS 흐름을 수정할 때 확인해야 할 테스트, import, 검증 기준을 정리함
- 구조 변경 시 타입과 파일명이 같이 맞는지 확인하는 데 집중함

---

## 1. 테스트 관점

- 프레임워크 연결이 아니라 유스케이스 동작을 테스트함
- 성공 흐름과 예상 실패 흐름을 모두 다룸
- payload 형식이 계약의 일부라면 그 부분도 테스트함
- 구조화된 에러 매핑이 중요하면 그 부분도 테스트함

## 2. CQRS 테스트 형태

- 핸들러가 받는 메시지 클래스를 직접 생성함
- 유스케이스 로직은 핸들러를 직접 호출해 검증함
- 실제로 필요한 협력자만 모킹함

## 3. 린트와 import 정리

- import는 정렬하고 최소화함
- 리팩터 후에는 unused import를 바로 제거함
- 파일명과 export 심볼은 같이 맞춤
- 읽기성과 drift 방지를 위해 필요한 곳에는 명시적 타입을 둠

## 4. 검증

- 메시지 shape나 핸들러 시그니처를 바꿨다면 타입체크를 실행함
- 파일명, export, import를 바꿨다면 린트를 실행함
- event나 DTO shape가 바뀌면 관련 테스트도 함께 갱신함
