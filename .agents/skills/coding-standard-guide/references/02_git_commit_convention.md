# Git 커밋 컨벤션 가이드 (Git Commit Convention Guidelines)

본 프로젝트의 모든 커밋 메시지는 일관된 히스토리 관리와 가독성을 위해 아래의 규칙을 준수하여 **한국어**로 작성합니다.

---

## 1. 커밋 메시지 기본 구조

```
<type>(<scope>): <subject>

<body> (선택 사항)

<footer> (선택 사항)
```

- **예시**: `feat(database): 엔티티 내 Swagger 데코레이터 통합`

---

## 2. 타입(Type) 규격

커밋의 성격을 직관적으로 파악할 수 있도록 아래의 타입을 접두어로 사용합니다.

| 타입 (Type) | 설명 |
| :--- | :--- |
| **feat** | 새로운 기능 추가 |
| **fix** | 버그 및 타입 오류 수정 |
| **docs** | 문서 및 가이드라인 추가/수정 |
| **style** | 코드 포맷팅, 세미콜론 누락 등 동작에 영향을 주지 않는 변경 (CSS 스타일 포함) |
| **refactor** | 코드 리팩터링 (버그 수정이나 기능 추가가 없는 코드 개선) |
| **test** | 테스트 코드 추가 및 수정 |
| **chore** | 빌드 프로세스 변경, 패키지 관리자 설정 수정 등 기타 단순 작업 |

---

## 3. 영역(Scope) 규격

모노레포의 영향 범위를 명확히 알기 위해 아래의 모듈 키워드를 소괄호 안에 기입합니다.

| 영역 (Scope) | 설명 |
| :--- | :--- |
| **database** | `@pkg/database` 엔티티 및 스키마 변경 |
| **shared** | `@pkg/shared` 공유 유틸리티/타입 변경 |
| **service** | `apps/platform-service` 플랫폼 서비스 비즈니스 로직 및 API 변경 |
| **auth** | `apps/platform-service` 내 인증 도메인 관련 변경 |
| **frontend** | 어드민 포탈 웹앱(`web/platform-admin-web`) 관련 변경 |
| **agents** | `.agents/` AI 에이전트 스킬 및 가이드라인 파일 변경 |

---

## 4. 제목(Subject) 작성 원칙

1. **한국어 작성 원칙 (Korean First)**
   - 모든 커밋 메시지는 명확하고 이해하기 쉬운 **한국어 작성을 필수**로 합니다.
2. **긍정형 지시어 사용 (Positive Directives)**
   - 무엇을 변경했고 어떤 동작을 수행하는지 명시적이고 긍정적인 명령형 어조로 간결하게 작성합니다.
   - 금지 문구(부정 표현)나 "A 대신 B를 적용함" 등의 비교형 설명은 사용하지 않습니다.
     - *적절한 예시*: `refactor(core): 요청 페이로드 타입 추출 및 CQRS 핸들러 간소화`
     - *부적절한 예시*: `refactor(core): 지저분한 인라인 타입을 사용하지 않고 파일로 추출함` (금지 표현 포함)
