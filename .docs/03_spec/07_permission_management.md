# 권한 관리 메뉴 기능명세서 (FE)

## 1. 개요

* 각 역할 그룹(SYSTEM_ADMIN, PARTNER_OWNER 등)에게 부여되는 권한 세트(Permission Set) 정의 기능 제공.
* 각 리소스(Menu/Component)의 액션(CREATE, READ, UPDATE, DELETE)별 허용 여부를 격자 행렬(Matrix) 형태로 일괄 설계 및 갱신함.
* 구현 파일: `web/platform-admin-web/src/routes/_protected/permissions/index.tsx` (라우트 경로: `/permissions`).

## 2. 메뉴 식별 정보

| 항목 | 값 |
| --- | --- |
| 메뉴명 | 권한 관리 |
| 리소스 코드 | `PERMISSION` |
| 리소스 유형 | `MENU` |
| 리소스 범위 | `PLATFORM` |
| 경로 | `/permissions` |
| 아이콘 | `Shield` |
| 기본 권한 | `CREATE`, `READ`, `UPDATE`, `DELETE` |

## 3. 메뉴 목적

| 목적 | 설명 |
| --- | --- |
| 권한 세트 구조화 | 개별 역할에 바인딩할 수 있는 논리적 권한 묶음(예: `SYSTEM_OPERATOR`)을 생성하고 관리함. |
| 미세 접근 제어 (FGA) | 메뉴 단위뿐만 아니라 개별 컴포넌트(버튼, 링크)의 작업 범위(CRUD)를 세밀하게 제어함. |
| 상속 및 종속 관계 보호 | 부모 메뉴의 접근 인가 상태에 종속되는 하위 요소들의 권한 정합성을 자동 제어함. |

## 4. 화면 구성

### 4.1 좌측 권한 세트 목록 패널 (`PermissionSetList`)
* **목록**: 등록된 권한 세트의 이름, 코드, 설명 및 해당 세트가 배정된 사용자 수(`assignmentCount`) 표시.
* **추가 단추**: 새로운 권한 세트 생성 모달 트리거 수행.

### 4.2 우측 권한 매트릭스 편집 패널 (`PermissionMatrix`)
* **헤더**: 선택된 권한 세트의 코드 정보 및 저장되지 않은 임시 변경 사항 감지 알림 제공.
* **리소스 매트릭스 테이블**:
  * 리소스 계층(MENU/COMPONENT)과 고유 코드 및 제약 조건 표시.
  * `CREATE`, `READ`, `UPDATE`, `DELETE` 액션별 토글 버튼 및 행 전체 체크 스위치 제공.
  * 리소스가 해당 액션을 미지원할 시 비활성화(Deactivated) 취소선 표출 수행.
* **하단 정보 바**: 권한 상속 종속성 정책 가이드 표출.

## 5. 데이터 모델

### 5.1 권한 세트 (PermissionSet)

| 필드 | 설명 |
| --- | --- |
| `id` | 권한 세트 고유 식별자 (UUID) |
| `code` | 권한 세트 코드 (대문자 및 언더스코어 조합, 예: `SYSTEM_OPERATOR`) |
| `name` | 권한 세트 이름 |
| `description` | 권한 세트 부가 설명 |
| `permissionCodes` | 부여된 개별 권한들의 코드 집합 (`['MEMBER:READ', 'MEMBER:CREATE']`) |
| `assignmentCount` | 본 세트가 할당된 매니저 수 |

## 6. 기능 상세

### 6.1 신규 권한 세트 추가 및 템플릿 복사
* 새 권한 세트 등록 시 기존에 구성된 다른 권한 세트의 권한 목록을 초기 템플릿으로 복사(`copyFromId`)하여 생성 효율성을 제고함.

### 6.2 권한 상속 종속성 및 자동 정제 규칙 (Sanitization Rules)
* **[상위 메뉴 의존성 규칙]**:
  * 하위 컴포넌트(`COMPONENT`)의 권한은 부모 리소스(`MENU`)의 권한과 상속 관계를 형성함.
  * 부모 리소스(`MENU`)의 `READ` 권한이 유효하고, 동시에 `CREATE`, `UPDATE`, `DELETE` 중 1개 이상의 쓰기 권한이 셋에 포함되어 있을 때만 하위 `COMPONENT` 권한 생성을 허용함.
  * 부모 메뉴의 권한 조건이 충족되지 않으면 하위 컴포넌트 권한 체크는 정제 로직(`sanitizePermissionCodes`)에 의해 자동으로 탈락(`false`) 처리됨.

### 6.3 실시간 변경 감지 및 일괄 저장
* 행렬(Matrix) 내의 임시 체크 상태를 감지하여 변경사항이 존재하는 경우 헤더에 `저장되지 않은 변경사항 있음` 경고 배지 점멸하고, `저장` 및 `초기화` 버튼을 활성화함.

## 7. 상태 판정 규칙

### 7.1 권한 매트릭스 액션 상태
| 판정 기준 | UI 표시 상태 | 설명 |
| --- | --- | --- |
| 액션 미지원 리소스 | 회색 취소선 및 점선 테두리 | 해당 리소스는 해당 CRUD 행위가 지원되지 않음 |
| 액션 지원 + 선택됨 | 각 액션별 고유 테마 활성 배지 (초록/파랑/노랑/빨강) | 현재 권한 세트에 포함되어 정상 작동하는 상태 |
| 액션 지원 + 선택 해제 | 회색 테두리 배지 | 권한이 부여되지 않은 상태 |

## 8. 입력 검증

| 항목 | 검증 규칙 |
| --- | --- |
| 권한 세트 코드 | 필수 입력, 공백 제거 후 대문자 자동 정규화 및 언더스코어 치환 검증 |
| 권한 세트 이름 | 필수 입력, 최소 1자 이상 검증 |
| 설명 | 선택 입력 |

## 9. 사용자 피드백

| 상황 | 피드백 |
| --- | --- |
| 변경사항 미저장 탈출 시도 | 브라우저 이탈 방지 경고창 혹은 탭 잠금 처리 수행 |
| 코드 중복 검사 실패 | 토스트 메시지 출력: `이미 존재하는 권한 세트 코드입니다.` |
| 저장 성공 | 토스트 메시지 출력: `'[이름]' 권한 세트의 퍼미션 구성이 저장되었습니다.` |

## 10. API 연동 기준

| 기능 | Method | Endpoint | DTO | 비고 |
| --- | --- | --- | --- | --- |
| 권한 세트 전체 조회 | `GET` | `/api/v1/resources/permission-sets` | 없음 | 사이드 바 리스트업용 조회 |
| 권한 세트 생성 | `POST` | `/api/v1/resources/permission-sets` | `CreatePermissionSetDto` | 복사 템플릿 코드 포함 제출 지원 |
