# 감사 로그 및 고객 지원 메뉴 기능명세서 (FE)

## 1. 개요

* 플랫폼 내에서 발생한 주요 시스템 조작(CRUD) 이력 감사 기능 제공.
* 파트너사 조직으로부터 인입된 기술 지원 티켓(Ticket) 조회 및 처리 상태 관리 기능 제공.
* 구현 파일:
  * **감사 로그**: `web/platform-admin-web/src/routes/_protected/audit/index.tsx` (라우트 경로: `/audit`)
  * **고객 지원**: `web/platform-admin-web/src/routes/_protected/support/index.tsx` (라우트 경로: `/support`)

## 3. 메뉴 목적

| 목적 | 설명 |
| --- | --- |
| 보안 감사 및 추적 | 관리자 및 외부 사용자가 수행한 CRUD 조작 결과(SUCCESS/FAILURE)와 트랜잭션 페이로드를 상세 추적함. |
| 고객 접수 기술 티켓 추적 | 각 조직에서 발송한 서비스 장애 및 문의(Ticket) 내역과 긴급도 수준을 조회함. |
| 사후 추적 정합성 제공 | 작업 일시, 수행 IP 주소, 대상 리소스 ID 등을 매칭하여 문제 해결 컨텍스트를 보존함. |

## 4. 화면 구성

### 4.1 감사 로그 화면 (`/audit`)
* **검색 및 필터 카드**: 키워드 입력(수행 계정, 변경 대상, IP), 액션 필터(CREATE, READ, UPDATE, DELETE), 결과 필터(SUCCESS, FAILURE) 제공.
* **감사 데이터 테이블**: 일시, 수행 계정, 액션 배지, 변경 대상, 수행 IP, 결과 배지, 상세 조회 돋보기 단추 배치.
* **보안 감사 상세 다이얼로그**: 트랜잭션 발생 시 인가 프레임워크가 캡처한 메타데이터 JSON 페이로드(`details`)를 코드 포맷팅 뷰어로 렌더링함.

### 4.2 고객 지원 화면 (`/support`)
* **티켓 목록 테이블**: 제목, 조직 ID, 우선순위 배지, 상태 배지, 등록일, 상세 보기 액션 버튼 노출.

## 5. 데이터 모델

### 5.1 감사 로그 (AuditLogMock / AuditRecord)

| 필드 | 설명 |
| --- | --- |
| `id` | 감사 로그 고유 식별자 |
| `actor` | 행위를 수행한 사용자 계정 이메일 |
| `action` | 수행한 데이터 액션 유형 (`CREATE` / `READ` / `UPDATE` / `DELETE`) |
| `target` | 감사 대상이 된 자원 식별자 문자열 |
| `ipAddress` | 행위자 접속 클라이언트 IP 주소 |
| `status` | 트랜잭션 결과 (`SUCCESS` / `FAILURE`) |
| `timestamp` | 사건 발생 일시 (UTC) |
| `details` | 데이터베이스 변경 트랜잭션 세부 메타데이터 (JSON String) |

### 5.2 기술 지원 티켓 (SupportTicket)

| 필드 | 설명 |
| --- | --- |
| `id` | 티켓 고유 식별자 (UUID) |
| `title` | 기술 문의/티켓 제목 |
| `content` | 기술 문의 본문 내용 |
| `status` | 티켓 현재 처리 진행 단계 (`OPEN` / `IN_PROGRESS` / `RESOLVED` / `CLOSED`) |
| `priority` | 긴급성 정도 (`LOW` / `MEDIUM` / `HIGH` / `URGENT`) |
| `createdAt` | 티켓 발행 접수 일시 |
| `organizationId` | 문의를 접수한 파트너사 조직 식별자 |

## 6. 기능 상세

### 6.1 감사 레코드 필터링 및 JSON 상세 뷰어
* 감사 로그 화면 목록 조회 시 액션 유형 및 결과 상태 셀렉터를 변경하면 클라이언트 사이드 메모리 리스트가 반응형으로 필터링됨.
* 개별 행의 `상세` 버튼 클릭 시, 다이얼로그 내부에 트랜잭션 메타데이터(HTTP 헤더, Access Denied 원인 코드, 추가/삭제된 권한 목록 등)를 syntax-highlighted 코드 블록 형태로 표시함.

### 6.2 고객 지원 티켓 상태 및 우선순위 분기
* 티켓 우선순위(`priority`)가 `URGENT` 또는 `HIGH`인 경우, 관리자가 즉시 식별할 수 있도록 적색/경고 배지 디자인 바인딩 수행.
* 일반적인 `LOW`/`MEDIUM` 등급은 차분한 슬레이트 배지로 매핑함.

## 7. 상태 판정 규칙

### 7.1 감사 결과 상태
| 판정 기준 | UI 표시 상태 | 설명 |
| --- | --- | --- |
| `status = SUCCESS` | SUCCESS (초록색 배지) | 인가 검사를 통과하여 정상 데이터베이스 트랜잭션 반영 성공한 상태 |
| `status = FAILURE` | FAILURE (빨간색 배지) | 권한 미달 또는 유효성 실패로 차단/반려된 트랜잭션 상태 |

### 7.2 티켓 처리 상태
| 판정 기준 | UI 표시 상태 | 설명 |
| --- | --- | --- |
| `status = OPEN` | OPEN (외곽선 배지) | 접수되어 분석 대기 중인 상태 |
| `status = IN_PROGRESS` | IN_PROGRESS (노란색 배지) | 담당자가 배정되어 문제 해결을 수행 중인 상태 |
| `status = RESOLVED` | RESOLVED (초록색 배지) | 해결 완료 처리된 상태 |
