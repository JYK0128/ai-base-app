# 공지게시판 vs 공지팝업 비교 문서

## 1. 요약

| 구분 | 공지게시판 | 공지팝업 |
| --- | --- | --- |
| 정의 | 공지 콘텐츠를 관리하고 게시 상태를 제어하는 도메인 | 같은 공지 콘텐츠를 특정 조건에서 노출하는 도메인 |
| 핵심 목적 | 공지 콘텐츠의 누적 관리와 게시 제어 | 같은 공지 콘텐츠를 접속 맥락에 맞게 노출 |
| 주요 사용자 | 운영자, 관리자 | 최종 사용자, 접속 사용자 |
| 데이터 성격 | 공지 원본 데이터 | 공지 원본의 노출 데이터 |
| 핵심 판단 기준 | 게시 여부, 게시 기간, 대상, 우선순위, 고정 여부 | 노출 조건, 노출 시점, 닫힘 여부, 재노출 여부 |
| 적용 범위 기준 | 공지 관리와 게시 제어 중심 | 공지 원본의 노출 범위와 노출 순서 중심 |

## 2. 공통 콘텐츠 기준

| 항목 | 설명 |
| --- | --- |
| 공통 콘텐츠 | 공지게시판과 공지팝업은 같은 공지 원본 콘텐츠를 사용함 |
| 콘텐츠 책임 | 제목, 본문, 대상, 기간, 상태는 하나의 공지 원본에서 관리함 |
| 사용 책임 | 공지게시판은 원본을 관리하고, 공지팝업은 원본을 현재 접속 맥락에 맞게 노출함 |
| 분리 기준 | 원본 데이터와 노출 규칙, 노출 순서, 노출 위치를 분리해 다룸 |
| 시스템 다이얼로그 | 공용 알림/확인 UI와 공지팝업은 분리해서 다룸 |

## 3. 공지게시판 필요 항목

| 항목 | 설명 |
| --- | --- |
| 공지 생성 | 새 공지를 등록하는 기능 |
| 공지 수정 | 기존 공지 내용을 변경하는 기능 |
| 공지 조회 | 특정 공지 또는 목록을 확인하는 기능 |
| 공지 삭제 | 더 이상 필요 없는 공지를 제거하는 기능 |
| 게시 상태 제어 | 초안, 예약, 게시, 종료 상태를 관리하는 기능 |
| 게시 기간 설정 | 시작일과 종료일을 지정하는 기능 |
| 노출 대상 분리 | 전체, 플랫폼, 조직 등 대상별 노출 제어 기능 |
| 우선순위 제어 | 공지 간 노출 순서를 조정하는 기능 |
| 상단 고정 | 중요한 공지를 우선 노출하는 기능 |

## 4. 공지게시판 구현 항목

| 구분 | 구현 항목 | 현재 경로 |

| 백엔드 | 공지 CRUD 컨트롤러 | `apps/platform-service/src/domains/announcement/announcement.controller.ts` |

| 백엔드 | 생성/조회/수정/삭제 핸들러 | `apps/platform-service/src/domains/announcement/*` |
| 데이터 | 공지 엔티티 | `packages/database/src/domains/platform/announcement/announcement.entity.ts` |
| 데이터 | 공지 분류, 대상, 우선순위, 상태 상수 | `packages/database/src/domains/platform/announcement/announcement.constants.ts` |

| API | 수정 | `PUT /api/v1/announcements/:id` |
| API | 삭제 | `DELETE /api/v1/announcements/:id` |

## 5. 필요 데이터 항목 비교

| 항목 | 공지게시판 필요 여부 | 공지팝업 필요 여부 | 설명 |
| --- | --- | --- | --- |
| `id` | 필요 | 필요 | 공지를 식별하는 값 |
| `title` | 필요 | 필요 | 공지의 제목 |
| `content` | 필요 | 필요 | 공지의 본문 |
| `category` | 필요 | 선택 | 공지게시판은 분류 관리가 핵심이고, 공지팝업은 분류를 운영 메타로 둘 수 있음 |
| `audience` | 필요 | 필요 | 공지 대상 범위 제어에 사용됨 |
| `priority` | 필요 | 필요 | 여러 공지 중 우선 순서를 정할 때 사용됨 |
| `pinned` | 필요 | 선택 | 공지게시판의 상단 고정에 사용됨 |
| `publishedAt` | 필요 | 필요 | 게시 또는 노출 확정 시점을 관리함 |
| `startAt` | 필요 | 필요 | 게시 또는 노출 시작 시점을 관리함 |
| `endAt` | 필요 | 필요 | 게시 또는 노출 종료 시점을 관리함 |
| `status` | 필요 | 필요 | 초안, 예약, 활성, 종료와 같은 상태를 관리함 |
| `isPublished` | 필요 | 선택 | 게시 확정 여부를 나타냄 |
| `author` | 필요 | 선택 | 작성자 추적이 필요한 경우 사용함 |
| `createdAt` | 필요 | 필요 | 생성 시점을 추적함 |
| `updatedAt` | 필요 | 필요 | 수정 시점을 추적함 |
| `sortOrder` | 선택 | 필요 | 여러 팝업이 동시에 존재할 때 노출 순서를 제어함 |

## 6. 공지게시판 도메인 규칙

| 규칙 | 설명 |
| --- | --- |
| 생성 규칙 | 제목, 본문, 대상, 분류, 우선순위를 기준으로 공지를 등록함 |
| 게시 규칙 | 게시 확정 여부와 게시 기간을 기준으로 노출 가능 여부를 판단함 |
| 상태 규칙 | 초안, 예약, 게시, 종료 상태를 분리해 관리함 |
| 우선 노출 규칙 | `pinned` 값으로 상단 우선 노출 여부를 판단함 |
| 대상 규칙 | 공지 대상에 따라 전체 또는 특정 조직 범위로 제한함 |
| 수정 규칙 | 기존 공지의 핵심 속성과 게시 조건을 갱신함 |
| 삭제 규칙 | 게시 이력과 식별자를 유지한 채 제거 정책을 적용함 |

## 7. 공지팝업 도메인 규칙

| 규칙 | 설명 |
| --- | --- |
| 등록 규칙 | 제목, 본문, 대상, 노출 기간, 우선순위를 기준으로 팝업을 등록함 |
| 노출 규칙 | 대상, 시점, 조건을 만족할 때만 팝업을 노출함 |
| 순서 규칙 | 여러 팝업이 동시에 유효하면 순서 값으로 노출 우선순위를 결정함 |
| 범위 규칙 | 공지 원본의 노출 범위를 기준으로 팝업을 선택함 |
| 재노출 규칙 | 사용자가 `하루 다시보지 않기`를 선택하면 24시간 동안 다시 노출하지 않음 |
| 종료 규칙 | 노출 기간 종료 또는 비활성화 시 팝업 노출을 중단함 |
| 닫기 규칙 | 사용자가 닫은 팝업은 재노출 정책에 따라 다시 보여줌 |
| 이력 규칙 | 사용자별 노출 여부와 닫기 여부를 기록함 |

## 8. 구현 관점 비교

| 관점 | 공지게시판 | 공지팝업 |
| --- | --- | --- |
| 백엔드 | CRUD, 목록 조회, 상세 조회, 게시 정책, 삭제 정책 | 노출 대상 조회, 발행 조건 판정, 닫기 및 재노출 정책 |
| 데이터 모델 | 제목, 본문, 분류, 대상, 우선순위, 고정, 게시 기간, 상태 | 제목, 본문, 노출 조건, 종료 시점, 닫기 상태, 순서 |
| 상태 판단 | 게시 여부와 기간을 기준으로 상태를 계산함 | 노출 가능 조건과 사용자 행동을 기준으로 상태를 계산함 |
| 생명주기 | 작성, 수정, 게시, 만료, 삭제 | 등록, 노출, 닫기, 재노출, 종료 |
| 검증 포인트 | 필수 입력, 예약 기간, 상태 판정, 게시 확정 처리 | 조건 충족 여부, 중복 노출 제어, 닫기 후 재노출 규칙 |

## 9. 권장 정리 기준

| 기준 | 설명 |
| --- | --- |
| 공지게시판 정의 | 운영자가 관리하는 콘텐츠 저장소로 유지함 |
| 공지팝업 정의 | 같은 공지 원본의 노출 규칙을 별도 관리함 |
| 데이터 분리 | 원본 속성과 노출 속성을 분리함 |
| API 분리 | 관리 API와 노출 API를 분리해 유지함 |
| 재노출 정책 | 팝업 닫기 상태와 재노출 규칙을 별도 관리함 |
